# 长庆工程图纸智能审查 · 开发指南

> 本仓库是**架构骨架**，给开发人员克隆后在框架内填实现。  
> PP-DocLayoutV3、Qwen 抽取、Image-to-Graph、CAD 量距 **都还没写**，只留了接口桩。本审查点不用 MinerU。  
> 配套图：`docs/架构图-系统分层架构.drawio`、`docs/架构图-审查点开发做法.drawio`。  
> 上位设计：`技术方案详细设计.md`（以投标为准；版面检测主选型 **PP-DocLayoutV3**）。

---

## 1. 先记住三句话

1. **前端不调智能体。** Vue 只打后端 `/api/*`。
2. **后端不写审查算法。** FastAPI 只接文件、调 `ai.graph.invoke(task)`、落库回写。
3. **审查点不是新智能体。** 一个点 = `ai/rules/*.yaml`（抽取字段 + `checks`）。目录索引一致性另有一张工作流图 `ai/graph/toc_index.py`，由总控 `invoke` 按 skill 进入，不要再写第二个入口。

## 2. 目录放什么

```
审查框架/
├── 开发指南.md                 ← 本文件（开发入口）
├── README.md
├── requirements.txt
├── ai/                         ← AI 运行时（审查算法只允许出现在这里）
│   ├── graph/controller.py     ← 【冻结】总控，唯一入口 invoke(task)
│   ├── tools/                  ← 工具注册中心 + 桩
│   │   ├── registry.py         ← 【冻结签名】need → 工具
│   │   ├── operators.py        ← 比对算子（set_diff / eq / seq）
│   │   ├── layout_yolo.py      ← 【算法组实现】版面检测（文件名历史遗留；**实现应对齐投标 PP-DocLayoutV3**）
│   │   ├── pdf2png.py          ← 【算法组实现】图纸转 png
│   │   ├── extract_*.py        ← 【算法组实现】抽 toc / 标题栏 / 图例 / 图 / 总图
│   ├── prompts/                ← 提示词库（抽取提示词只放这里，代码按 id 加载）
│   ├── rules/                  ← 审查规则库（审查点开发只改这里；抽取只写 prompt id）
│   ├── agents/                 ← 审查执行器 + 校验（按 YAML 跑，不要复制）
│   ├── compile/                ← 编译面：规则转换（客户改规则才跑）
│   ├── state.py / issue.py     ← 【冻结】状态与 Issue schema
├── backend/                    ← 服务层空壳（任务 / 权限以后接 RuoYi）
├── frontend/                   ← 展现层空壳（用公司 Vue3 脚手架初始化）
├── data/                       ← 运行时上传与结果（不入库）
├── scripts/                    ← 启动与冒烟
└── docs/                       ← 架构图与约定、技术方案，只读
```

| 你负责 | 去这个目录 | 不要去 |
|--------|------------|--------|
| 审查点（目录一致性、防火间距…） | `ai/rules/` 加 YAML，抽取提示词放 `ai/prompts/` | `ai/graph/`、`backend/` 里写比对或写提示词 |
| 版面检测（PP-DocLayoutV3） | `ai/tools/layout_yolo.py`（或改名后的 layout 实现文件）函数体 | 审查点 YAML、前端 |
| 目录抽取 / 标题栏 VLM（Qwen3.8） | 信息抽取智能体 `ai/agents/extract_info.py`；其他审查点的空桩在 `ai/tools/extract_*.py` | 每个审查点各抽一遍 |
| P&ID Image-to-Graph | `ai/tools/extract_pid_graph.py` | 新建「P&ID 总控」 |
| 总图 CAD 量距 | `ai/tools/extract_site.py` | 在 Vue 里算间距 |
| 新比对算子（如 `min_distance`） | 先平台同意，再改 `ai/tools/operators.py` 并在执行器登记 | YAML 里发明 `op` 名 |
| 规则自建（人话→Skill） | `ai/compile/compiler.py` | 改总控边 |
| 上传、任务、报告 API | `backend/app/` | `from ai.tools.layout_yolo import …` |
| 页面、预览、问题列表 | `frontend/` | 浏览器直连大模型 |

## 3. 冻结清单（不能动 / 动了必须平台评审）

下列文件**边、节点名、函数签名、字段名**冻结。算法组可以改「函数内部怎么算」，不能改「叫什么、入参出参、谁调用谁」。

| 文件 | 冻结内容 | 允许 |
|------|----------|------|
| `ai/graph/controller.py` | 唯一入口 `invoke(task)`。`form.toc_index` 进入 `toc_index` 图；其余点仍是 `detect → extract → review → validate` | 平台组修 bug。新审查点默认只加 YAML；确需自己的流程图时挂到 `invoke`，禁止再起 FastAPI |
| `ai/state.py` | `ReviewState` 字段 | 扩展字段走评审 |
| `ai/issue.py` | `ISSUE_KEYS` | 禁止审查点私自定义键 |
| `ai/tools/registry.py` | `NEED_TO_TOOL`、`register(name, produces)`、`fill(needs, …)` | 新增工具：加映射 + 新文件并 `@register` |
| `ai/agents/form_review.py` | 按 YAML `op` 调算子，不写具体条款 | 新 `op` 时加一个分支（与 operators 同步） |
| `ai/agents/validate.py` | 只校验 Issue 结构 | 可加置信度闸门，不改审查结论 |
| `backend/app/services/review.py` | 只能 `from ai.graph.controller import invoke` | 落库、任务状态 |
| `frontend/` | 只调 `/api/tasks` `/api/review` `/api/skills` | 交互与展示 |

**禁止事项（审查即打回）：**

- 为某个审查点再起一个 FastAPI，或绕过 `invoke(task)` 直接调模型。目录索引的流程图只允许在 `ai/graph/toc_index.py`。
- 审查点 Python 里直接 `import` YOLO、OpenAI。
- 前端、后端服务层写 `set_diff`、抽标题栏、调 GPU。
- 改 `Issue` 字段名（`desc`/`basis`/`suggestion` 等）而不走平台。
- 把编译面（规则转换）塞进每张图的执行路径。

## 4. 执行面怎么跑（每套图）

```
后端 POST /api/review
  → ai.graph.invoke(task)
       detect   调 layout.detect（YOLO 桩）
       extract  按本次 Skill 的 needs 并集调工具，同一工件只抽一次
       review   读 ai/rules/*.yaml，跑 operators，产出 Issue
       validate 检查 Issue 字段
  → 后端落 JSON，前端展示
```

任务信封（后端传给总控）：

```python
{
  "task_id": "...",
  "project_id": "...",
  "files": [{"id": "...", "name": "...", "path": "..."}],
  "skill_ids": ["form.toc_index"],   # 空则跑全部 enabled Skill
  "storage_dir": "..."
}
```

`needs` 与工具对应关系（改映射必须同步文档）：

| needs | 工具名 | 实现文件 |
|-------|--------|----------|
| `layout` | `layout.detect` | `layout_yolo.py` |
| `toc` | `extract.toc` | `extract_toc.py` |
| `title_block` | `extract.title_block` | `extract_title_block.py` |
| `file_list` | `extract.file_list` | `extract_file_list.py` |
| `legend` | `extract.legend` | `extract_legend.py` |
| `pid_graph` | `extract.pid_graph` | `extract_pid_graph.py` |
| `site_features` | `extract.site_features` | `extract_site.py` |
| `notes` | `extract.notes` | `extract_notes.py`（说明栏文本行：版面 YOLO 裁「说明」框 → 切条 → VLM 抄写；PNG 直接输入，PDF 先转 PNG） |

工具返回值约定：顶层 key = 工件名。未实现时保留 `"_stub": true`，总控会跳过依赖该工件的审查点，避免空数据误报。

## 5. 审查点开发（业务组）

1. 复制 `ai/rules/_template.yaml` 为 `ai/rules/<pack>.<name>.yaml`。
2. 填写 `id` / `name` / `pack`（`form` | `pid` | `site`）/ `basis` / `needs` / `checks`。
3. `checks.op` 只能是已登记算子：`set_diff` | `eq` | `seq` | `required_fields` | `flag_items` | `catalog_align` | `expect` | `seq_audit` | `llm_judge`。
   `llm_judge` 仅限错别字等语义类点（技术方案 §8.4），白名单、阈值、判定范围全在 YAML；示例 `form.notes_typo.yaml`，白名单 `_notes_glossary.yaml`（下划线开头的文件不会被当成 Skill 加载）。
4. 准备正例、反例图纸各 ≥1，回归时断言 Issue 的 `type` 与条数。
5. 把 `enabled` 设为 `true`。不要改 `controller.py`。

目录索引一致性在 `form.toc_index.yaml`：`extract` 规定目录和各文件要抽的字段，`checks` 用 `catalog_align` 比对公共字段、文件号、版次、自然张数。执行图是 `ai/graph/toc_index.py`。

## 7. 编译面（仅客户改规则）

日常审图 **不走** `ai/compile/`。  
甲方用自然语言改规则时，由规则转换智能体改写 `ai/rules/*.yaml`，人工确认 + 回归后生效。图的边不变。

`compiler.py` 目前是桩。平台组在此接大模型，禁止审查点开发人员改总控来「适应新规则」。

## 8. 前后端

当前后端是 **FastAPI 空壳**，便于 AI 联调。正式环境按投标接 **RuoYi + XXL-Job**，仍然只 `invoke(task)`。

```text
GET  /api/health
GET  /api/skills
POST /api/tasks          multipart 文件
GET  /api/tasks/{id}
GET  /api/tasks/{id}/result
PATCH /api/tasks/{id}/issues/{issue_id}   {"review_status":"confirmed|rejected|pending"}
POST /api/review         {"task_id","skill_ids"}
POST /api/review/folder  {"folder","skill_ids"}
```

`frontend/` 是目录索引一致性的简易审查台，由审查服务在 `/` 提供。页面只提交文件夹和复核结论。审查过程与问题列表以任务 id 落在后端。正式环境仍换公司 Vue3 脚手架，接口不变。

## 9. 本地跑起来

在**本仓库根目录**（含 `ai/`、`backend/` 的这一层）：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/smoke.py          # 无目录文件时给出 missing_catalog
python scripts/test_toc_rules.py # 目录比对算子离线回归
python scripts/run_toc_index.py --folder "<含目录.doc 的文件夹>"
python scripts/run_api.py        # 本框架 API。不要占用 192.168.31.9:8000 上的大模型
$env:PYTHONUTF8=1; langgraph dev --no-browser   # Studio，图名 toc_index。中文 Windows 必须开 PYTHONUTF8
```

Studio 输入示例：`{"folder": "C:/Users/zzx13/Desktop/长庆/某站形式审查", "skill_ids": ["form.toc_index"]}`。图框权重 `../best.pt`（类别 `title_block`，`imgsz=1280`，`conf=0.5`）。

大模型走 OpenAI 兼容接口，配置写在仓库根目录 `.env`（已 gitignore）。内网 vLLM 默认 `http://192.168.31.9:8000/v1`；当前开发用阿里云百炼 `qwen3.8-27b`（`VLM_PROVIDER=dashscope`，关闭思考用 `enable_thinking: false`）。抄写/审查需要 JSON，**不用**官方示例里的 `stream=True` 和 `enable_thinking: True`。复制 `.env.example` 为 `.env` 后填密钥即可。

说明栏错别字（`form.notes_typo`）：

```bash
python scripts/test_notes_typo.py                       # 离线回归，不访问模型
$env:NOTES_DETECT_SOURCE="label_json"                   # 开发态：没有版面权重时读与 PNG 同名的标注 JSON 里的「说明」框
python scripts/run_notes_typo.py --folder "<含 PID PNG 的文件夹>" --only-extract   # 只抄写，调提示词用
python scripts/run_notes_typo.py --folder "<含 PID PNG 的文件夹>"                  # 抄写 + 错别字判定
```

版面权重在 `192.168.31.9:/data/zzx/图纸处理/runs/cq_layout/weights/best.pt`（类别 `图框/表格/说明`，训练 `imgsz=1536`）。`NOTES_DETECT_SOURCE=remote` 时经 SSH 在服务器上推理，本机只收回说明框再裁图，不用把 `best.pt` 拷下来。账号写在 `.env` 的 `YOLO_REMOTE_*`。本机另有权重时用 `NOTES_DETECT_SOURCE=yolo`，`YOLO_IMGSZ_LAYOUT` 默认 1536，`YOLO_CONF_NOTES` 默认 0.3。该权重的图框类别名是 `图框` 而不是 `title_block`，与旧图框权重不通用。

不要把 `demo/`（若你还能看到上级目录里的联调 demo）里的真实抽取代码拷进本骨架冒充实现。本仓库才是开发基线。
