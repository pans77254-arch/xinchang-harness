# AI 智能体框架 · 给全组的架构与开发约定

> 技术经理下发。所有审查点、所有人，必须在本框架内开发。禁止另起工作流引擎或私自新增「总控」。  
> 配套图：`架构图-审查点开发做法.drawio`（审查点怎么挂框架）+ `架构图-系统分层架构.drawio`

---

## 1. 这套架构可不可以

**可以，而且必须按这套做。** 一人一个审查点，但点不是系统：点是挂到框架上的**工作流包**。智能体和工具允许随任务增加，但只能**注册进框架**，不能每人复制一套。

| 做 | 不做 |
|----|------|
| 把审查点写成工作流，交给**审查智能体**执行 | 为某个审查点再写一个总控 / 再起一个 FastAPI |
| 缺能力时向**工具注册中心 / 智能体注册中心**加插件 | 在审查点代码里直接调 PP-DocLayout/MinerU 各写一遍 |
| Issue 用统一 schema 回后端 | 私自定义报告字段 |

---

## 2. 前后端与 AI 如何配合

```
用户 → 前端 Vue3 → 后端 RuoYi（落库、权限、任务）
                 → 队列 XXL-Job / RabbitMQ
                 → AI 运行时 LangGraph
                      总控智能体.invoke(task)
                 ← 统一 Issue 列表
后端落报告 → WebSocket 推前端 → 可选回写二维协同
```

- 前端不直接调智能体。  
- 后端不写审查逻辑，只发任务、收结果、管用户和文件。  
- AI 侧只认一种任务信封：`project_id / files / workflow_ids[] / callback`。

## 3. 智能体框架（AI 部分，全组共用）

运行时：**LangGraph**。总控是图的入口，不是让大模型现场随便选工具。

### 3.1 执行面（每套图都跑）

| 智能体 | 职责 | 谁可以改 |
|--------|------|----------|
| **总控智能体** | 接后端任务；按图纸类型加载工作流包；编排检测→提取→审查→校验；汇聚后回写后端 | 仅平台组 |
| **图纸检测智能体** | 图框/版面（**PP-DocLayoutV3**，投标基座）。主路径由总控调用；失败可整图 VLM 兜底 | 算法组 |
| **信息提取智能体** | 把图/文档变成工件：title_block、toc、legend、pid_graph、site_features。内部用 MinerU、VLM、I2G、CAD | 算法组 |
| **审查智能体** | **只执行已注册的审查点工作流**。开发人员的交付物挂在这里 | 平台组维护执行器；业务/审查点开发只交工作流 |
| **校验智能体** | 工件是否齐全、JSON schema、检测失败则整图兜底、Issue 格式/置信度闸门、低置信进人复核 | 平台组 |

### 3.2 编译面（仅新规则入库，投标 3 Agent）

| 智能体 | 职责 |
|--------|------|
| **形式规则转换智能体** | 人话/Excel → 形式类工作流（字段、目录、跨图） |
| **P&ID 规则转换智能体** | 人话 → 拓扑/Cypher 类工作流 |
| **总图规则转换智能体** | 人话 → 空间量距类工作流 |

产出经人工确认 + 回归后，**写入工作流注册中心**，此后由审查智能体执行。已确认清单里的点：开发期直接写工作流注册，不必每次过转换智能体。

### 3.3 两个可增长的注册中心

- **智能体注册中心**：以后加「电气审查智能体」只注册，总控配置里打开即可。  
- **工具注册中心**：MinerU、PP-DocLayoutV3、Qwen、I2G、ezdxf、CAD COM、向量检索… 随任务增加。  
- **工作流注册中心**：每一个审查点一条。这是审查点开发人员的唯一入口。

## 4. 审查点开发人员交什么（强制格式）

每人负责一个审查点 = 向**工作流注册中心**提交一份包，**不是**提交一个新智能体。

必须包含：

1. `workflow.yaml`（或 JSON）  
   - `id` / `name` / `pack`（形式 | pid | 总图 | 关联）  
   - `level`：`project` 或 `drawing`  
   - `needs`：依赖哪些工件（总控据此先调检测/提取，禁止工作流里再调一遍检测）  
   - `steps`：有序列表（抽哪个字段、用哪个算子、阈值、规范条款）  
   - `on_fail`：缺工件时交给校验智能体，还是直接报错  
2. 正例 / 反例图纸各 ≥1  
3. 回归断言：期望 Issue 条数与 `issue_type`

统一 Issue 字段（不许扩展私有键，要扩展走平台评审）：  
`issue_id, drawing_no, skill_id, type, severity, desc, basis, suggestion, x, y, confidence, review_status`

审查智能体只跑 `eq / regex / seq / set_diff / cypher / min_distance / llm_judge` 等已登记算子。没有的算子先向平台申请，再写点。

---

## 5. 和「一人一个点」怎么兼容

总控按任务里的 `workflow_ids` 扇出到审查智能体，**一个点一份工作流，一份进程，同一套智能体**。点变多，只增加注册表行数，不增加总控数量。
